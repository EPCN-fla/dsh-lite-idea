0.2.0 — Subagents, faster sessions and profile-aware bridge setup

  • Read-only subagent sessions: browse direct children of the active main session and open their transcripts without resuming, closing or changing the main conversation. The subagent action appears only when the current session actually has direct children.
  • Fast, self-refreshing history: ACP owns ordinary session membership while bridge metadata enriches titles and subagents. Initial rows render before slow title requests, visible dialogs update in place, and first-open titles refresh automatically.
  • Local session catalog cache: reopen history instantly from the previous snapshot, reuse fresh bridge metadata for 60 seconds, and avoid repeated title lookups. Expired data refreshes in the background without replacing fresh ACP membership with cached roots.
  • Reliable session reuse: an untouched blank session survives switches to other history and IDE restarts. Real content, nonempty history or deletion clears the reuse marker; startup archive state is initialized before the first welcome refresh.
  • Independent transcript restoration: cache root and subagent transcripts, share concurrent imports, request root-only temporary exports and clean only bridge-owned temporary files.
  • Agent change review: track per-session created/modified files through VFS, ACP and final Git status; open HEAD/current diffs while excluding pre-existing dirt and retaining the last reliable result when Git fails.
  • Compatible bridge installation: detect the host and select the highest compatible published SemVer from npm registry metadata, preferring stable releases. Detection, registry or compatibility failures stop before any profile mutation.
  • Source-profile imports: install only stable workspace/bridge activation rows, then preview model/preset imports from any source profile in the same DSH_HOME with explicit conflict policy, reviewed revisions, host locking, backups and atomic writes.
  • Connection and asynchronous-state hardening: retry stale discovery candidates newest-first, distinguish installed-but-disconnected packages in Doctor, and keep busy/configuration state isolated by session during reconnects and rapid switches.

0.1.1 — Reliability and Web configuration import

  • Preview and explicitly import models and agent presets from the Web configuration with bridge 0.4.0 or newer, including conflict policy, revision checks and actionable results.
  • Move ACP and bridge protocol writes off the UI thread, bound control RPCs, and clean up agent process trees and pending requests during timeout, reconnect and project close.
  • Make session switching reliable under rapid interaction: preserve the latest selection and draft, serialize bridge subscriptions, reject stale list results and reset stale controls.
  • Restore live tool updates and interrupted states from history, and bound archive, shell, decompression and diagnostic output sizes.
  • Honor WSL UNC distributions and configured target environments across launch, discovery, Doctor and bridge installation; pass package specs without shell interpolation.
  • Encode file-mention resource links correctly, disable Swing HTML for untrusted tool text, restrict Markdown link protocols and preserve fenced-code formatting.
  • Improve thought-card refresh, tool-result parsing, localized tool labels and plaintext credential-storage guidance.

0.1.0 — Initial public release

  • Chat with DeepSeek Harness over ACP from the DSH tool window, with streaming Markdown, tables, collapsible reasoning, tool-call details, plan/todo display and context usage.
  • Create and resume project sessions; restore reasoning and tool results from history. Bridge integration adds session titles, rename/delete actions and ZIP log export.
  • Choose models, reasoning effort, agent presets and permission modes from the composer; approve tool requests in native dialogs or cancel an active turn.
  • Use the / command palette, browse skills and reference project files with @.
  • Install or repair the shared dsh-vscode-bridge profile from the toolbar, with version-aware setup for supported dsh releases and Doctor diagnostics.
  • Run the agent on Linux/macOS, Windows or WSL with automatic path mapping and support for custom environment variables.
  • Includes English and Simplified Chinese interface resources, IDE-aware typography, and chat layouts that adapt to tool-window resizing.

Before you start: use an IDE based on build 243 or newer and Node.js 22.19 or newer on the agent side. Configure a model provider in dsh. The bridge installer requires a POSIX shell (Linux, macOS or WSL); native Windows bridge setup is manual.
